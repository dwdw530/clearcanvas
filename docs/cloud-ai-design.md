## 1. 结论与范围

需要修改程序，不能只添加地址和 API Key。新增可选的「云端 AI」修复路径，复用现有文件导入、蒙版识别、预览、原图/结果切换和图片另存。

首版目标：用户在软件内配置中转地址、Key、模型，选择云端模式后，对单张 JPG/JPEG/PNG 自动识别或手动框选水印，确认上传，取得可检查的修复预览，再另存。

### 分期边界

| 功能 | 首版 | 后续阶段 |
| --- | --- | --- |
| 现有本地图片、PDF、批量流程 | 保留，不改变算法 | 持续回归 |
| 单张图片：自动识别 + 云端修复 | 支持 | 扩大样本与接口适配 |
| 单张图片：精细修复范围 | 支持初选、补选、擦除、撤销、缩放和拖动 | 按实际用户反馈调整 |
| AI 设置、密钥保护、接口测试 | 支持 | 多配置档按需要增加 |
| 云端 PDF 当前页、多页、混合批量 | 不支持、不上传 PDF | 单独设计授权、调用预算及文字层损失确认 |
| 本地 AI 模型 | 不新增 | 不因云端设计自动恢复此方向 |
| 自动重试、多模型兜底、自动分块、多张候选 | 不支持 | 仅在费用与效果验证后讨论 |
| AI 检测全部水印、恢复被遮住的真实原文 | 不承诺 | 与 AI 修复能力分开评估 |

设计以一份可用的修复结果为目标，而不是新增聊天界面或整图创作工具。首版每次操作最多提交一次图片编辑请求；不自动拆成多次付费请求。

## 2. 已知接口与未确认能力

### 2.1 用户提供的接口线索

```text
中转服务：https://code1.newcli.com/
请求接口：POST https://code1.newcli.com/v1/images/edits
鉴权：Authorization: Bearer <用户在软件中填写的 Key>
模型：gpt-image-2
请求体：multipart/form-data
示例参数：prompt、size=1536x1024、quality=high、response_format=b64_json
图片字段：image（示例为两张参考图；去水印请求使用一张处理图）
```

上述最初为用户提供的文档示例。2026-10-25 分别获用户确认后，生成图一次及指定人像/彩色边角各一次真实请求均为 HTTP 200、返回 1 张 1536×1024。两张指定图片通过构图检查，导出原尺寸 PNG，人工视觉画质待验收。均不发送 `mask` 或 `n`，无重试，实际费用未知。详见 [验收记录](cloud-ai-candidate-report.md)。模型名称按中转要求发送，不自动换成 Image 2.5，也不据别名确认上游真实模型身份。

### 2.2 能力状态

| 项目 | 当前依据 | 设计处理 |
| --- | --- | --- |
| 原像素裁剪上传 | 旧缩放补边预设三次请求通过；本轮原像素上传仅离线验证 | 原像素不先降采样，新请求须由用户逐次确认，中转兼容性不冒称已验证 |
| Base64 图片返回 | 三次请求按 `b64_json` 返回且解码成功 | 已验证本次配置，不代表其他协议 |
| 返回 `data[0].b64_json` | 现有严格解码器对真实响应校验通过 | 三次均为 1 张且尺寸匹配 |
| `mask` 蒙版参数 | 真实测试未确认支持 | 当前兼容方式不发送，移除用户开关及旧配置的生效路径 |
| 按比例输出尺寸 | 上游官方图片协议支持 16 像素对齐；用户选择保真优先，中转尚未实测 | 总像素不超过旧预设，不发 `auto`、不增加质量档位，失败不换参数重试 |
| 默认出图数量、最大输入、耗时和价格 | 三次不传 `n` 均为 1 张；生成图/人像/边角为 25.297/32.875/43.422 秒 | 不保证未来数量/稳定时延；最大输入及价格未确认 |
| 稳定性、人像保真、内容限制 | 旧请求与本轮离线几何分析不等于真实细节还原 | 先检查既有结果，不以水印消失或范围外像素不变认定画质合格 |

即使服务支持 `mask`，模型也可能改变蒙版外内容。必须本地合成保护原图，并单独检查返回图的构图对应关系。

## 3. 界面与交互

### 3.1 主界面：保持原生工作台

沿用 PySide6 / Qt、现有中性灰白背景、青绿色主操作、Lucide 图标、Microsoft YaHei UI，不改成网页、聊天或浮动卡片界面。

- 顶部增加「设置 → AI 接口设置」。
- 右侧文件信息面板上方增加「修复方式」：`本地处理` / `云端 AI`，以及「AI 接口设置…」链接式次级按钮。
- 初次启动、每次重新启动均默认本地，不因保存了 Key 就自动启用云端。
- 保留处理、对比和导出位置，但主按钮明确区分「本地一键去水印」「AI 去水印」和「重新生成 AI（可能计费）」。
- 选择云端时，常驻显示「会上传处理图像，可能产生费用」，状态栏显示实际服务域名。
- 结果标签注明来源，例如「云端 AI 结果」，模型放在结果信息内；不能仍显示为全程「本地」。
- 切换修复方式、修改设置不会重新调用接口，也不丢弃已有结果。导出依据结果来源，而不是当前下拉框。
- AI 结果的「批量导出」禁用并说明「首版云端 AI 暂不支持批量」。本地结果的原有批量不受影响。
- 打开 PDF 时明确切回本地并提示「当前版本的 PDF 仅支持本地处理，不会上传」。返回图片时不自动恢复云端。
- 已收图片在右侧提供查看/调整与另存入口；右侧面板可滚动，避免小窗口中的任务操作不可达。

### 3.2 AI 接口设置对话框

采用原生 `QDialog`，可随 DPI 调整布局。可见标签、键盘焦点与 Tab 顺序完整，不依赖占位文字或悬浮提示。

```text
AI 接口设置

服务地址 *  [ https://code1.newcli.com/            ]
实际接口    https://code1.newcli.com/v1/images/edits

API Key *   [ •••••••••••••••••••          ] [显示]
[ ] 安全记住 Key（Windows 凭据管理器）
[删除已保存的 Key]

模型名称 *  [ gpt-image-2                         ]
请求尺寸    [ 按修复区域比例 / high / 原预设像素预算 ]

高级选项：图片编辑兼容方式（不提交未确认的区域文件）、超时时间

[测试图片接口（可能计费）]      [取消] [保存设置]
```

规则：

1. 地址允许输入 HTTPS 服务根或带 `/v1` 的 API 根，规范化后仅追加一次 `/images/edits`；实时展示实际请求地址。
2. 首版只接受上述两种根形式；其他路径提示不支持，不能盲目截断用户路径。拒绝 URL 中的用户名、密码、查询串和片段，禁止 HTTP 与忽略证书错误。
3. URL、模型、Key 的必填和格式校验全部在本地完成；输入、保存、打开设置不联网。
4. Key 默认隐藏，可主动显示；不回填假 Key 占位符作为真实值。删除已保存 Key 需确认，作为草稿在保存时生效，取消对话框不删除凭据。
5. 不勾选「安全记住」时仅本次运行使用；勾选后由 Windows 凭据管理器保存，普通配置中没有 Key。
6. 保存凭据失败时明确提示，允许用户选择仅本次使用，不能静默明文落盘或声称保存成功。
7. 使用单图图片编辑字段，不发送未确认的区域文件；不存在让用户猜测支持情况的「提交蒙版」开关。输出尺寸来自本次计划，旧固定 `size` 和 `send_mask` 不再生效，保存设置时清理，不访问网络。
8. 等待超时默认总计 300 秒，可在 60–600 秒间调整；连接阶段限制 15 秒。这是产品预算，不代表模型实测速度。
9. 修改地址、Key、模型或超时时间后，上次接口测试结果失效；测试可选，不要求使用前每次重新付费测试，也不将测试成功当成画质通过。
10. 设置保存不自动选择云端，不清空当前结果。设置草稿取消不写配置或凭据；处理中禁止测试和修改生效配置。

### 3.3 接口测试：不是无成本的“连接成功”

按钮命名为「测试图片接口（可能计费）」，不能用 ping 或 `/models` 成功冒充图片编辑成功。

- 使用程序生成的测试图，同样走原像素裁剪与按比例尺寸计划；不读取或上传用户当前文件。
- 提交前确认域名、模型、一次请求以及可能计费；用户可取消。
- 执行一次图片编辑请求，检查 HTTP 状态、JSON、Base64、图片解码与尺寸。
- 显示「图片编辑接口验证通过」，不显示「去水印效果已通过」。
- 测试不包含尚未确认的 `mask` 参数，不偷偷追加探测请求；返回尺寸必须匹配该次计划。
- 测试结果绑定配置版本，只证明这次图的协议及尺寸，不证明所有比例兼容；没有打开文档也能测试。
- 不能从本地测试推断中转未披露的单价、模型身份或远端数据保留策略。

### 3.4 单图处理流程

1. 用户打开原始图片并主动选择云端模式；保存 Key 不自动启用云端。
2. 「AI 去水印」在本地生成初选范围；没识别到时提供空范围编辑，不自动上传。手动矩形也先转换为可精细编辑的范围。
3. 第一步解释橙色是本地允许修改的范围、不是结果，支持补选、擦除、撤销、缩放和拖动；确认后重建原像素上传裁剪及按比例输出计划。
4. 第二步分别显示原图、上传裁剪和请求输出尺寸，以及完整上传内容、范围、中转兼容性与费用提醒；「确认上传并生成（可能计费）」才提交一次请求。
5. 提交后显示上传、生成、校验和本地合成阶段；失败不重试，不换模型，不拆成多次请求。
6. 安全返回图保留到替换或退出。尺寸不匹配、明显构图变化、缺失内容或无法可靠对齐都禁止合成，仍可查看与另存；不确定状态不能人工强制通过。
7. 只有对齐通过，或受限校正重新通过并经人工确认后才合成。展示原图、完整返回图和实际合成预览，分别检查水印、五官与接缝；明确使用后才替换有效结果。
8. 暂不使用或关闭核对不会丢图。可合成的已收图允许离线调整范围，不用 Key、不新增请求；范围不得超出已有上传裁剪或校正后的可用内容。无法合成的图只提供查看和另存。
9. 重新生成是新的计费请求，仍需范围和费用确认；取得新图后替换当前保留图，失败保留旧图。退出时未另存的返回图需选择保存、明确放弃或取消退出。

失败或取消保留原图和上次有效结果；已收到的安全图不会因关闭核对或取消离线调整而释放。不自动写磁盘或用完整 AI 图默认覆盖原图。

## 4. 图像处理方案

### 4.1 请求计划：单图、单次、保留上下文

- 使用现有 EXIF 方向归一化和图像安全限制，不上传磁盘原文件或原文件路径。
- 上传图在内存重新编码为 PNG，使用通用文件名 `input.png`，不携带原始 EXIF、GPS、文件名等元数据。
- 局部水印可围绕全部待处理蒙版取一个有上下文的裁剪区域；跨鼻翼、唇线等结构时保留足够的周围结构，不能逐个字符抠图。
- 平铺或分散水印采用覆盖全部待处理区域的单一大裁剪，必要时全图。不会自动拆成多块、多次请求。
- 上传保留裁剪区域原像素，不缩放、不补边；透明像素仅按既有方式合成到中性底色，原 alpha 留在本地。重新编码的 PNG 超过 32 MiB 时停止，不擅自降质。
- 输出依据 [OpenAI 图片编辑协议](https://developers.openai.com/api/reference/resources/images/methods/edit) 选择 16 像素对齐的尺寸，在接近裁剪比例的相邻网格中择优，总像素为 655,360 至 1,572,864，不增加旧预设的输出像素预算。裁剪比例超出 1:3 至 3:1 时仍可编辑范围，但不能上传。
- 本地对齐参考图按返回尺寸等比缩放，并记录微小补边与裁剪映射；它不是上传文件，不把原图非等比拉伸。高分辨率输入的返回图仍可能较小，原尺寸导出不保证修复细节完整。
- 过大的修复区域继续沿用当前安全上限：不超过图像 30% 且不超过 200 万像素；不自动放宽现有边界。
- 保存原始蒙版 `M`，最终修改区域严格受 `M` 约束。需要扩大边界时必须把扩大后的区域显示给用户，不隐式侵占保护区。

2026-11-13 用户明确选择保真优先，允许先按标准协议实现按比例尺寸并做离线验证；这不等于中转兼容性已确认，也不授权真实测试。原像素输入可能增加费用；预算不增加不能保证单价或总费用不变。远端 `mask` 继续等待该中转的可靠依据，不试探、不自动重试。

### 4.2 固定接口兼容方式与本地修复范围

- 当前使用上传图片和固定去水印指令，不发送未确认的 `mask` 参数；接口设置不提供蒙版开关，旧开关不再生效。
- 原始本地修复范围 `M` 始终控制最终合成，不提交区域文件不意味着允许 AI 结果覆盖全图。
- 自动识别的范围可以由用户补选、擦除；发送前重新裁剪并生成保护区，用于后续构图检查。
- 已收到图片后调整的是本地合成范围，不改变原请求，也不重新联网。新增范围超出上传裁剪、面积超限或校正后缺失内容时明确拒绝。
- 如果以后增加其他协议，须以服务文档与单独授权验证为依据，不自动猜测、试探或失败后删参数重试。

### 4.3 固定指令与请求字段

首版不提供任意创作提示词编辑器，避免把去水印变成人物替换。提示词围绕下列要求生成：

> 仅删除现有水印并自然填补被覆盖区域。严格保留输入图片的画面边界、长宽比例和构图；不要扩图、补画画外的衣服或背景，不要移动、缩放、拉伸人物。保持人物身份、姿势、鼻孔、鼻翼、嘴唇、肤色、头发、光照和背景不变；不要美化、换脸、重构五官或添加文字。保留非水印正文，不推测或补写被遮挡的原文。

这只是给模型的指令，不是保真保证。

- 请求使用用户示例已出现的 `model`、`prompt`、`size`、`quality`、`response_format` 和单个 `image` 字段。
- 不发送尚未确认的 `mask` 或其他区域参数，不提供用户手动试错开关。
- 不默认添加多张参考图、`n`、高保真开关等未在该中转示例中确认的参数。
- 目标是一张结果；若中转默认生成数量不是一张，必须先查明数量控制协议及费用，再放行产品调用。

### 4.4 响应校验与合成

顺序不可省略：

1. 检查 HTTP 成功状态及响应格式，禁止把 HTML 网页、聊天文字或错误对象当图片。
2. 按接口测试确认的响应结构提取一张 Base64 图片。缺字段、空数据或多张不符合单结果约定时失败，不猜测字段。
3. 流式限制响应：首版原始响应最多 64 MiB、解码后文件最多 32 MiB，并遵守当前 4000 万像素限制；超过预算明确报错。
4. Base64 严格解码，Pillow 验证静态图片；首版仅接受 PNG/JPEG，拒绝动画、SVG 和外链 URL，不自动访问远端返回的链接。
5. 安全解码后检查返回画布尺寸；不同尺寸禁止拉伸合成，但图仍保留为可查看、另存的完整返回画布。
6. 在原有保护区检查 ORB 特征与 RANSAC 对应，排除透明区、修复区及本地参考补边。角点位移不超过 3 个返回画布像素且证据充分时可判为对齐；不能据此证明五官未变。受限校正要求至少 40 个内点、内点比例至少 0.75、覆盖跨度至少 35%、至少三个象限各有四个内点，角点位移不超过 12 个返回画布像素、缩放偏差不超过 0.5%、旋转不超过 0.25°。原蒙版及插值邻域必须全部落在可用内容区，补边不算源内容；校正后重新检查仍须对齐，并经人工确认。
7. 保护区不足或无法可靠判断时只提供查看和另存，禁止合成，UI 和底层都不能用确认标志绕过。受限校正展示按返回尺寸显示的原图对照、完整返回和校正图。安全图与原请求计划保留到替换或退出，关闭核对不释放；另存 PNG 去元数据、原子写入并保护原件。已发生的费用不能由本地拒绝撤销。
8. 按已记录的补边、缩放、裁剪逆变换恢复修复区。只更新原图的 `M` 内 RGB，首版保持原 alpha；半透明保护区不因 AI 返回值改变。
9. 在各局部范围周围计算原图与返回图的颜色差，把仅来自受保护、近不透明背景的差值延伸到修复区，补偿局部明暗而保留 AI 细节；其他修复区和透明像素不作为背景参考。只提交 `M` 内 RGB，不向范围外羽化或扩大写入；没有不透明参考时保留原返回像素，并仍须通过实际预览确认。
10. 再次核对原文件戳，构造独立结果，然后显示原图、完整返回图和实际合成预览。对齐通过、接缝统计下降或范围外像素不变都不证明人像画质合格。

PNG / 内存结果验收：原件哈希不变、输出尺寸不变、`M` 外 RGBA 逐字节一致。JPEG 会因重编码发生全图像素变化，界面和文档必须区别说明。

## 5. 网络、密钥与隐私

### 5.1 最小依赖方案

优先复用已安装的 `PySide6.QtNetwork`：`QNetworkAccessManager`、`QNetworkReply`、`QHttpMultiPart`，不为一个 HTTP 接口引入 OpenAI SDK、PyTorch、ONNX 或新增 requests/httpx 依赖。

本轮已验证开发环境能导入上述 QtNetwork 类和 `QSettings`；并不代表完成了网络实现或 Windows 构建验证。

### 5.2 网络线程与取消

- 新增独立 `AiRepairService`，网络 worker 在专属 `QThread` 的事件循环中创建、使用、释放全部 QtNetwork 对象。
- UI 通过排队信号启动、取消；在所属线程调用 `reply.abort()`，不跨线程直接操作 reply。
- 本地识别、编码、校验、合成复用现有串行 `PreviewService`；不把 300 秒网络等待塞进 PDFium / 本地任务执行队列。
- 控制器串联「本地准备 → 网络 → 本地校验合成」，整个操作使用任务 ID、配置版本、原件戳和取消状态，迟到结果不得覆盖新任务。
- 设置测试走独立的服务结果路由，不依赖 `MainWindow._active_key`；没有打开文件也可测试。与修复任务单飞，禁止并行提交。
- 网络等待阶段取消应在约 1 秒内反馈并中断本地连接；本地识别等受限计算仍在取消检查点停止，不承诺强杀线程。
- 明确提示：「取消只能停止本机等待，服务端可能仍在生成，已发生的费用不保证撤销。」
- 超时、断网、429、5xx 默认零自动重试。即使没有收到结果，也可能已计费。
- 取消后仍保留原件、旧结果及最近一次安全解码的返回图；清理网络 reply、multipart 和响应缓冲，不自动持久缓存。
- 最小化保留当前任务；退出需先结束任务，并对未另存返回图选择保存、明确放弃或取消退出，再关闭网络和本地工作线程。

### 5.3 地址与凭据

- 地址只允许 HTTPS，使用正常 TLS 证书验证，拒绝跟随重定向，尤其不能把 Authorization 转发给另一个域名。
- 用户主动设置的服务是信任边界；确认框始终显示实际目标域名。更换地址后要求重新确认，不复用旧测试状态。
- 普通设置用 `QSettings` 保存地址、模型、预设、超时及能力开关。
- Key 用 Windows 凭据管理器保存，优先小型标准库 `ctypes` 适配（`CredWriteW` / `CredReadW` / `CredDeleteW`）；不新增第三方密钥库。
- 凭据按规范化 API 根隔离，不因编辑域名就把旧站点 Key 自动带到新站点。缓存 Key 仅在内存用于本次会话，退出清理引用；不承诺内存取证层面的绝对擦除。
- 非 Windows 开发环境只支持会话 Key，不明文降级保存。
- Key 不进入源码、JSON 配置、进度档、结果对象、图像元数据、日志、错误信息或安装包；真实测试时仅通过软件设置输入。

### 5.4 数据边界与文案更新

- 打开、预览、切换模式、保存配置、导出已生成图片以及所有本地处理均不发网络请求。
- 只有用户确认的图片接口测试和云端修复会联网。裁剪也可能含脸部或敏感背景，不能描述成“只上传水印”。
- 不上传 PDF、密码、路径、EXIF；不读取外部文档链接。远端数据保留由中转及上游决定，软件不能承诺远端删除或不训练。
- 服务端错误按已知错误码给中文说明，使用纯文本、限长展示；不原样记录响应体，以免泄露密钥、图片或服务端敏感信息。
- 日志最多记录脱敏的任务阶段、耗时、状态码和尺寸，不记录图像内容或完整请求头。
- 实施后同步更新 README 与功能设计：由“文档处理不联网”改为“本地模式不联网，云端 AI 需明确授权上传”，不能继续声称全部处理都在本地。

## 7. 错误与恢复设计

| 情况 | 用户反馈与行为 |
| --- | --- |
| 缺地址 / Key / 模型 | 聚焦设置错误字段；不发送请求 |
| 无水印或选区超限 | 提示框选 / 分次处理；不上传 |
| 用户未同意上传 | 返回原状态；无请求 |
| TLS 错误、重定向 | 明确连接安全问题；不关闭验证，不跟随 |
| 401 / 403 | 检查 Key、额度/权限及服务限制；不回显 Key |
| 404 | 检查图片编辑接口地址或模型；不改用其他接口猜测 |
| 400 / 参数不支持 | 指明需核对模型、预设、蒙版协议；不删参数重试 |
| 429 | 提示限流/额度等可能原因，按响应可确认信息说明；不自动重试 |
| 超时、断网、5xx | 本次未取得有效结果，可能已计费；保留旧结果 |
| 缺图、坏 Base64、超限、外链、尺寸不符 | 拒绝作为成功结果，不生成可导出伪结果 |
| 明显构图变化 | 拒绝合成，提示调整方案；不靠强行缩放对齐 |
| 对齐判断不充分 | 保留完整返回图，仅可查看和另存，不能人工强制合成 |
| 原件处理中变化 | 丢弃本次结果，提示重新打开 |
| 用户取消或结果已过期 | 不覆盖预览；停止本机网络等待，清理任务 |

不把模型按内容策略拒绝的响应包装成连接故障，不设计绕过服务限制的自动提示词重试。

## 10. 设计建议汇总

1. 本地默认、云端主动选择；保存 Key 不等于同意上传。

### 11.2 实施任务拆分

| 优先级 | 工作 | 完成依据 |
| --- | --- | --- |
| P0 | 核对源码 / 用户改动 / 样本，冻结可用的 0.3.9 对照并记录输入哈希 | 缺样本明确列出，不能用跳过伪装真实画质通过 |
| P1 | `ai_settings.py` 与设置弹窗：地址规范化、配置、会话 Key、Windows 凭据、测试授权 | 本地字段校验、保存 / 取消 / 删除、密钥隔离测试通过；设置不会自动联网 |
| P2 | `ai_service.py`：独立 QtNetwork worker、单图 multipart、可注入模拟传输、限长响应、超时和取消 | 错误 / 重定向 / 取消 / 迟到结果测试通过；默认不重试 |
| P3 | `ai_repair.py`：请求计划、方向 / 裁剪 / 补边、可选远端 mask、严格解码、尺寸 / 构图检查、局部合成 | 合成真值与蒙版外像素保护测试通过；不靠整图拉伸修正错位 |
| P4 | 现有编辑器 / 窗口串联：模式选择、上传确认、分阶段预览、来源标签、导出与关闭保护 | 本地模式零网络；AI 图片导出零新请求；AI 批量 / PDF 在 UI 和底层都被阻止 |
| P5 | 文档 / 回归：使用范围、隐私费用、真实验证状态、必要安装包运行库审计记录 | 相关离线测试与现有回归通过；真实调用、打包和发布分别列为未验证 / 未执行 |
| P6 | 用户本地填写 Key 并明确同意后，做接口及指定人像真实验收 | 实际导出、前后对比、费用 / 请求次数与尚存画质问题；不得用测试数量代替 |

P1–P5 可以在没有真实 Key 的情况下推进成完整候选。默认模式始终本地，云端能力保持“实验性 / 真实效果待验证”说明，直到 P6 通过。用户可在候选界面本地输入 Key 并主动触发已确认的测试；程序不会后台自动做 P6。

源码接入点见第 6 节，错误行为见第 7 节，验收清单见第 8 节。无需为先跑通请求而删除安全、取消、费用或蒙版保护要求。

### 11.3 无 Key 时的交付边界

可以完成：设置与凭据管理、单图编辑请求代码、可取消网络服务、模拟响应、蒙版合成、Qt 交互和相关回归。

不能完成或声称完成：真实中转连通、响应结构实际兼容、默认出图数量、真实 `mask` 支持、价格 / 时延、人像视觉验收。代码按已提供示例构造候选请求，未知能力保持关闭或待验证；不能编造实测结果，也不能要求用户把 Key 粘贴进聊天。

如果单图真实验证失败，停止上线 / 发布并报告原因；不要擅自回滚已有代码、删除候选文件、改成多次请求或换其他模型试错。

### 11.4 验证与交付报告

在当前已安装环境中运行，不以安装新依赖为前提：

```bash
.venv/Scripts/python.exe -m pytest tests/test_ai_settings.py tests/test_ai_service.py tests/test_ai_repair.py tests/test_ai_ui.py -q
.venv/Scripts/python.exe -m pytest -q -rs --tb=short
.venv/Scripts/python.exe -m ruff check .
git diff --check
```

第一条列出拟新增的测试文件名；实施后以实际路径为准，不在文件尚不存在时执行。组件 / 字体专项跳过必须逐项说明；指定真实人像缺失不得被记作效果通过。全量测试失败先定位新旧原因，保留已有用户改动。

最终报告必须分开：代码已实现的内容、实际运行的测试与数量、真实接口 / 画质是否验证、打包 / 安装 / 提交 / 推送是否执行。更新同一原进度档，不另建“AI 接续”存档，不自动写长期记忆。
